# Risk register — Mosslight

Ordered by expected cost (likelihood × impact). "Where it is handled" names the phase or artifact that owns
the mitigation, so the roadmap can be checked against this table.

| # | Risk | Likelihood | Impact | Mitigation | Where it is handled |
|---|---|---|---|---|---|
| 1 | **Content is authored but unfinishable** — a key behind the door it opens, a one-way door, a spawn inside a wall. The game builds, passes unit tests, and cannot be completed. This is the single most likely way the run ships something that fails §15. | High | High | `content::validate` implements §7's full list, including a breadth-first reachability search over (room, item set) proving the ember is obtainable and the lighthouse reachable afterwards. It runs as a test, in CI, and at startup. The validator itself is tested against deliberately broken fixture worlds. Plus the headless start-to-victory test (§13) driving only ordinary actions. | ADR 0005; phase 3–4; `tests/content.rs`, `tests/playthrough.rs` |
| 2 | **We build the wrong game** — 15 rooms and a boss exist, but the 30–45 minute experience is unpaced: the sword is found too late, the dungeon is opaque, or the difficulty ramp of §7 (teach movement, then attack, then threats) never lands. Nothing automated catches this, and no human will play it before morning. | High | High | Encode the pacing requirement as content structure rather than intent: room 1 has no enemies and a movement/interaction prompt; the sword is in the second overworld room on the critical path; the first slime appears only after it. The headless playthrough asserts the *order* of the main-route milestones, not just the victory. Actual feel is recorded as an open question in the verification report rather than claimed. | Phase 3–4 content design; `tests/playthrough.rs`; verification report |
| 3 | **Time runs out mid-content** — the eight-hour ceiling arrives with the dungeon half-built, leaving stubs on the main route, which §14 forbids. | High | Medium | Phase order follows §14, and every phase ends on a working, completable build: after phase 2 the game is short but finishable. Content is added breadth-first (all rooms connected and traversable) before depth (secrets, extra dialogue, balance). Any shortfall against §2's content table goes into HANDOFF.md as named remaining work. | Roadmap phase gating; HANDOFF.md |
| 4 | **The terminal is left broken on some exit path** — raw mode still on after a panic or a SIGHUP. Over SSH the user may not be able to see what they type to recover. | Medium | High | One `TerminalGuard` with an idempotent `Drop`, a panic hook that restores before printing, signal flags polled by the main loop, a pre-raw-mode TTY/`TERM` check, and a hidden `--debug-panic` flag so the controlled-panic check in §13 can actually be executed rather than asserted. | ADR 0007; phase 1; manual check list |
| 5 | **ratatui/crossterm version skew** — the hazard §8 names by name: two crossterm versions in the graph producing incompatible event types, discovered as an inexplicable type error. | Medium | High | Depend on `ratatui = "0.30.2"` only and use `ratatui::crossterm`; `crossterm` never appears in `Cargo.toml`. A test asserts the lock file contains exactly one `crossterm` entry. Verified pair recorded in DECISIONS.md. | ADR 0003; phase 1; `tests/deps.rs` |
| 6 | **Input feels wrong over SSH** — stale moves replay after a stall, or a held key produces a runaway hero, or the game turns out to need key-release events. §5 calls this critical and the RTT check cannot be run here. | Medium | High | Press-only key mapping by construction (no release handling exists anywhere in the code); ≤ 32 events read per iteration; movement coalesced to ≤ 1 step per tick; pending game actions dropped when a menu or dialogue closes; ≤ 5 catch-up steps with surplus time discarded. The held-key check is runnable locally; the ~150 ms RTT check is marked unverified. | ADR 0001; `input.rs`; phase 1 + phase 5 |
| 7 | **Save data loss or a panic on a bad save file** — the one artifact a player cannot recreate. | Medium | High | Atomic temp+`sync`+rename, one retained `.bak`, two-pass version probe, explicit `LoadOutcome` with no `unwrap` on the path, refusal to overwrite a future version, and the rule that a death state never overwrites a usable save. Tests for round-trip, corrupt file, and incompatible version are on §13's mandatory list. | ADR 0006; phase 5; `tests/save.rs` |
| 8 | **Render rate leaks into simulation speed** — the game runs faster or slower at `--fps 10` than at 20, which §15 fails on directly. | Medium | Medium | Fixed 30 Hz tick with integer tick time; `--fps` gates only the draw call; a test advances the simulation over a fixed action sequence and asserts the resulting state is identical at every fps setting. | ADR 0001, ADR 0002; `tests/loop_timing.rs` |
| 9 | **Boss fight is unbeatable or trivial** — two phases, telegraphs, and a vulnerability window are hard to balance with no human playtest, and the boss sits on the only route to victory. | Medium | Medium | All combat values in `game::tuning` as tick counts, so balance is a one-file change. Both boss phases and the final victory are on §13's mandatory test list, and the headless playthrough must beat the boss using ordinary actions — which sets a concrete upper bound on how unbeatable it can be. A scripted "no-damage-taken" assertion checks the vulnerability window is real. | `game::tuning`; `tests/boss.rs`, `tests/playthrough.rs`; phase 4 + phase 6 |
| 10 | **Monochrome or ASCII mode is unreadable** — colour quietly becomes the only way to tell a bush from a wall, failing §4 and §15. | Medium | Medium | Glyph is the primary channel and every object type has a distinct ASCII glyph; the theme layer can only change colour, never glyphs, so a monochrome regression is structurally impossible. `TestBackend` tests assert the rendered *characters* of a scene, which means the ASCII assertions are the same assertions in every theme. | `render/tiles.rs`, `render/theme.rs`; `tests/render.rs`; phase 5 |
| 11 | **Layout breaks at 60×24 or on resize** — the scene is clipped, or a resize drops the hero into a hit they could not see coming. | Medium | Medium | Layout budget computed and fixed: 48+2 columns and 21 rows inside a 60×24 minimum, with slack. Below the minimum the game enters a `TooSmall` screen, pauses, and shows required versus current size; on recovery it resumes into **Paused**, never straight into play. Resize events coalesce to the last size per iteration. Tested at 60×24 and 80×24 via `TestBackend`. | §9 handling in `app.rs`; `tests/render.rs`; phase 1 |
| 12 | **Terminal output volume is too high over SSH** — constant redraw makes the game laggy on a real link, which §13 asks to be measured. | Low | Medium | ratatui's buffer diffing plus a dirty flag: no draw when nothing changed, no full-screen clear, and no decorative animation (§4). Menus and pauses redraw only on state change, so a paused game emits ~0 bytes. Measured locally with a byte-counting writer and reported with the environment named. | ADR 0001; `render/`; phase 5 measurement |
| 13 | **Clippy debt discovered late** — the intake forbids deferring lint work, and an unattended run finding a large pile at 3 a.m. burns a phase. | Low | Medium | The full gate (`fmt --check && clippy -D warnings && test --locked`) runs at the end of every phase from phase 1 onward, so the pile can never exceed one phase of work. | Every phase gate |
| 14 | **Enemy AI gets stuck** — an enemy wedged in a corner makes a room look broken, and a stuck boss makes it unwinnable. | Low | Medium | Room-local BFS bounded to 24×16 with a deterministic fallback to local movement when no path exists; stable `Vec` iteration order as the tie-break for contested tiles. Per-kind state machines are small enough to test exhaustively; a test runs each enemy type for 1000 ticks in a maze room and asserts it never stops changing state. | ADR 0004; `game/ai.rs`; `tests/ai.rs` |
| 15 | **Unicode mode ships half-populated** — a partial tile set is worse than no Unicode at all and violates the intake's condition. | Low | Low | `--unicode` is treated as one atomic deliverable behind the same glyph-table abstraction as ASCII: either every tile has a verified-width Unicode glyph or the flag is not offered. If it is cut, the verification report says so. | `render/tiles.rs`; phase 5; verification report |
| 16 | **Extra dependencies creep in** — §8 permits only small libraries with a concrete need, and each one is a new version-skew surface. | Low | Low | The dependency set is fixed here: `ratatui`, `clap`, `serde`, `serde_json`, `ron`, `signal-hook`. Save paths and the PRNG are hand-rolled specifically to avoid two more. Any addition needs a line in DECISIONS.md naming the requirement it serves. | ADR 0003, ADR 0006; DECISIONS.md |
| 17 | **Linux / SSH / RTT claims are overstated** — §13 forbids claiming an unrun environment, and the pressure to tick every box at the end of an unattended run is exactly when this happens. | Low | Medium | The honest-claims boundary is fixed in advance (ADR 0008): CI covers the Linux build and tests; Intel macOS, aarch64 Linux, a real PTY SSH session, and the ~150 ms RTT check are labelled expected-but-unverified. The report is written from this list, not from optimism. | ADR 0008; verification report |
